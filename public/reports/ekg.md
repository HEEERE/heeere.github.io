# LLM4EKG — 技术报告

面向应急预案的知识图谱增强生成框架

作者：纪喆元｜角色：核心设计与开发｜项目时间：2025.05 — 2026.01｜状态：已完成

> 根据项目文档与作品集说明整理的设计与实现说明。验证方法为复核建议，流程演示采用本地预设数据；本报告不包含原始评测记录或独立复现结论。

## 系统实现与交付

- **双通道 / 信息抽取**：规则匹配与 LLM 抽取共同处理实体、条件、动作及隐式关系。
- **Neo4j / 结构化知识**：实体对齐后构建图谱，连接关系检索与原文证据召回。
- **Pipeline / 图谱构建管线**：DOCX 规则结构化、混合抽取入库与 PlanMeta 本体锚定。

## 问题与边界

应急预案具有长文档、条件分散和实体表述不一致的特点。LLM4EKG 将文档处理、实体对齐、知识图谱和检索增强问答串联起来，目标是让回答能够同时呈现关系与依据。公开仓库提供 DOCX 规则结构化、混合抽取及本体引导图谱构建的运行入口。

## 抽取与实体对齐

抽取阶段结合正则、模式匹配与大模型处理，识别组织实体、触发条件、处置动作和跨段落隐式关系。实体对齐结合 Embedding 相似度与中心性锚定聚类，减少同一实体的不同表述对图谱结构的干扰。

## 图谱与检索

对齐结果写入 Neo4j。回答问题时将实体关系检索与原文证据召回结合，使结论可以回到预案文本核对。现有设计包含 Entity Index、Rule Index 与 Emergency-SOP Benchmark，覆盖实体、规则及应急流程层面的评测组织。

## 设计取舍

规则通道便于解释和控制，LLM 通道有助于覆盖隐式表达，但会引入抽取不确定性。实体合并有误合并与漏合并的权衡。图谱检索提供关系结构，原文召回保留上下文；二者的覆盖范围需要分别评估。演示中的证据缺失提示是流程说明，不代表后端拒答策略已经验证。

## 个人贡献

- 结合正则、模式匹配与大模型抽取，识别组织实体、触发条件、处置动作及跨段落隐式关系。
- 使用 Embedding 相似度与中心性锚定聚类方法，缓解不同段落中同一实体表述不一致的问题。
- 基于 Neo4j 构建应急知识图谱，将实体关系检索与原文证据召回相结合，提高回答完整性与可解释性。
- 设计 Entity Index、Rule Index 与 Emergency-SOP Benchmark。

## 系统流程

Document → Parse → Extract → Align → Graph → Retrieve → Answer + Evidence

## 验证方法

- 抽取：对实体、触发条件、处置动作与关系分别标注并核对。
- 对齐：检查别名合并、同名实体及跨段落关系，保留冲突案例。
- 问答：比较检索方案的答案完整性、引用正确性和证据覆盖；记录数据集与模型版本。
